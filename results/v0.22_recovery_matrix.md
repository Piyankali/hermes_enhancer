# v0.22 Recovery Matrix

**Bound:** at most 100 buffer rows per `recover_buffered_events()` invocation.
Leftovers drain on later scheduler ticks or process startups.
**Metrics shape:** `{"recovered": N, "skipped": N, "states_seen": [...]}` —
`recovered` = newly persisted, `skipped` = already persisted (finalized
without insert). DB state, not counters, is the durable source of truth.

| Failure | Buffer state pre-recovery | Recovery action | Post state | Test |
|---|---|---|---|---|
| crash before final persist | CREATED | insert final + finalize | PERSISTED, 1 row | crash A |
| crash after final commit | CREATED + final row exists | detect via get_event, finalize only | PERSISTED, still 1 row | crash B |
| transient DB lock | CREATED | retry succeeds | PERSISTED | failure A |
| final tx failure | CREATED | retained, later tick recovers | PERSISTED | failure B |
| worker interruption | CREATED | fresh-instance auto-recovery | PERSISTED, 1 row | failure F |
| corrupt payload | any | FAILED + `corrupt_payload:` diagnosis, row kept | FAILED, preserved | failure D |
| unknown state | e.g. GARBLED | ignored, left in place | unchanged | failure D |
| duplicate event_id | exists | INSERT OR IGNORE / same row id | 1 row | failure E |
| backlog > 100 | N x CREATED | 100 per call | drains across calls | 500-backlog, crash C |
| simulated ENOSPC | CREATED retained | fail-loud, recover after clear | PERSISTED | storage suite |

Finalization (`PERSISTED` + `persisted_at`) is written only after the
final `sync_queue` commit for that `event_id` is confirmed.
