# v0.22 Durability Validation

**Scope:** process-crash/restart durability of the persistent event buffer.
**Date:** 2026-09-06
**Sources of truth:** `tests/test_v022_crash_recovery.py` (os._exit driver),
`tests/test_v022_startup_recovery.py`, `tests/test_v022_stress.py`,
`tests/test_v022_multiprocess.py`, `results/v0.22_final_gap_audit.md`.

## Tested guarantee

No duplicate persisted `event_id` and no loss of confirmed durable
buffered events across tested normal process crash/restart scenarios.

NOT claimed: universal exactly-once, power-loss/OS-crash durability
(`synchronous=NORMAL`, no fsync), physical disk-full (simulated only).

## Results

| Scenario | Evidence | Loss | Duplicates |
|---|---|---|---|
| crash after buffer COMMIT | crash A: 1/1 recovered, buffer PERSISTED | 0 | 0 |
| crash after final COMMIT | crash B: count stays 1, skipped path | 0 | 0 |
| 120-event crash/recovery | 100 + 20 across restarts | 0 | 0 |
| repeated crash/recovery | 3/3 exactly once | 0 | 0 |
| 10K sequential push | 10000/10000 unique | 0 | 0 |
| 10K concurrent (8 threads) | 10000/10000 unique | 0 | 0 |
| 4 procs x 1500 pushes | 6000/6000 unique, integrity PASS | 0 | 0 |
| 500-backlog recovery | batches exactly [100x5] | 0 | 0 |

## Ordering proof

`push()`: `enqueue_to_buffer()` (commit 1) -> `_insert_sync` + commit 2 ->
`mark_buffer_persisted()` (commit 3). Crash B observes buffer CREATED
alongside a committed final row pre-recovery, proving finalization never
precedes final persistence.
