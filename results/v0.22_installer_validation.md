# v0.22 Installer Validation

**Date:** 2026-09-07
**Scope:** `setup.sh` / `uninstall.sh` for Hermes Enhancer v0.22.0.

## Environment

- OS: Android (Termux), Linux-compatible user shell
- Shell: bash (`#!/usr/bin/env bash`, `set -euo pipefail`), standard
  coreutils + `python3` only — no sudo, no network, no rsync, no root
- Hermes Agent v0.21.0 CLI present (`hermes plugins list/show` read-only)
- Filesystem notes: `/tmp` is not writable here (temp dirs via
  `mktemp`/pytest `tmp_path` instead); the shared-storage repo mount
  ignores `chmod +x` mode bits, so tests invoke scripts via
  `bash <script>` and separately assert shebang + `bash -n` cleanliness

## Plugin discovery (how the real path was determined)

Three independent sources agree on `$HERMES_HOME/plugins/hermes_enhancer`
(default `$HOME/.hermes`), flat `.py` layout + `plugin.yaml`:
`tests/test_enterprise_upgrade.py` (`PLUGIN_DIR` constant), the legacy
`setup_plugin.sh`, and a live probe — a transient `probe_tmp` plugin dir
appeared in `hermes plugins list` (Source: user) and was fully removed.
`hermes plugins list --plain` is used for matching (Rich tables wrapped
names under pipes and caused false WARNINGs); index reads are cached, so
the check retries 5x10s. `hermes plugins doctor` was evaluated and
rejected as a gate: it fails on the pre-existing absolute-import style,
out of scope for this mission.
