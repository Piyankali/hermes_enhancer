### PHASE 6 — Startup Recovery: IMPLEMENTED + AUTOMATED TESTED
- `_ensure_initialized()` ends with `self._startup_recovery()`, which calls the existing `recover_buffered_events()` — recovery runs automatically on every normal `FederatedDB` initialization, after schema is ready, bounded to 100 rows/invocation (remainder left for worker/scheduler)
- Idempotent: startup + scheduler + manual recovery share the `event_id` UNIQUE guard; already-persisted events are counted as `skipped`, never duplicated
- Observable via `get_startup_recovery_info()` (`{"executed": True, "recovered": N, "error": None}`); no second worker or duplicate scheduler was added
- `tests/test_v022_startup_recovery.py`: 5/5 PASS (basic auto-recovery, idempotent double-startup, empty-DB startup, 5-event bounded batch, health preserved) — no test calls `recover_buffered_events()` after Process B starts

### PHASE 7 — Abnormal Crash Tests: IMPLEMENTED + AUTOMATED TESTED
- `tests/test_v022_crash_recovery.py` (4 tests) + `tests/crash_child.py` driver (not collected; modes: buffer_only, push_no_finalize, bulk, recover_then_die)
- Crash mechanism: separate OS process dies via `os._exit()` (codes 99/88/77) with no shutdown/flush/close; parent asserts nonzero exit, then starts a fresh `FederatedDB` — recovery only via automatic `_startup_recovery()`, never called manually post-restart; all state assertions use independent raw sqlite3 reads
- Crash-point injection is test-only (child stops after buffer commit, or monkeypatches `mark_buffer_persisted` to `os._exit` inside the child); production paths unchanged when the driver is absent
- Test A (buffer COMMIT → die): 1/1 recovered exactly once, buffer PERSISTED — Invariant A proven
- Test B (final INSERT+COMMIT → die before finalization): final count stays 1, buffer finalized, `skipped` path taken — Invariant B proven, finalization never precedes final commit
- Test C (120 events → die): startup N1 recovers exactly 100 (bound honored), N2 recovers 20; 120/120 final rows, zero duplicates, all PERSISTED
- Test D (crash → recovery → crash → recovery): 3/3 events exactly once, consistent buffer state
- Recovery bounded to a single ≤100-row batch per invocation (fixed offset-skipping bug found during this mission); backlog drains across scheduler ticks/restarts
- Telemetry gap: `events_persisted/events_failed/...` counters are in-memory per process and do not survive a crash; durability proven via DB state, not counters — no counters invented
- Durability boundary: process-crash/restart only. Power-loss durability NOT tested and NOT claimed.

### PHASE 8 — Failure Injection & Fault Recovery: IMPLEMENTED + AUTOMATED TESTED
- `tests/test_v022_failure_injection.py` (6 tests); injection is deterministic per-test `unittest.mock` patching only — disabled by default, no production path changes when inactive, no cross-test leakage
- Test A (transient lock): first `_insert_sync` raises `OperationalError("database is locked")`, retry succeeds; `events_retried`/`transient_errors` increment, 1 final row, buffer PERSISTED — PASS
- Test B (final tx failure): `_insert_sync` always raises; `push` raises (observable, `unknown_errors`+1), buffer stays CREATED, 0 final rows; scheduler-tick `recover_buffered_events()` then recovers 1/1 — PASS
- Test C (buffer write failure): `enqueue_to_buffer` raises; `push` AND `async_push` both raise (fail-loud rule added — buffer exceptions no longer swallowed), zero buffer/final rows, nothing falsely durable — PASS
- Test D (corrupt payload): recovery JSON-validates; corrupt row → FAILED + `corrupt_payload:` diagnosis, payload preserved, 0 final rows; unknown-state row left untouched; healthy row persisted 1/1 — PASS (reuses existing FAILED/last_error model, no new architecture)
- Test E (duplicate event_id): buffer 2nd insert False; double `push` returns same row id, 1 final row, 0 dupes; raw duplicate buffer INSERT raises IntegrityError (UNIQUE holds) — PASS. Required hardening: `_insert_sync` is now INSERT OR IGNORE plus partial unique index `idx_sync_queue_event_id_unique ... WHERE event_id != ''` (legacy empty-id rows exempt), returning the existing row id on conflict
- Test F (worker interruption): worker batch fails once (`events_failed`+1, 0 final rows, buffer CREATED survives); fresh instance auto-recovers to exactly 1, buffer PERSISTED — PASS
- Retry classification verified: transient (busy/locked OperationalError) retried via `_with_retry`/`_flush_buffer`; permanent/unknown counted (`permanent_errors`/`unknown_errors`) and surfaced, never retried forever
- Telemetry: `events_enqueued/persisted/dropped/failed/retried` + `transient/permanent/unknown_errors` verified logically consistent; `events_buffered/recovered/replayed/duplicates_prevented` do not exist as counters (recovery reports dicts instead) — documented gap, none invented; counters remain per-process memory, DB state is the crash-proof record
