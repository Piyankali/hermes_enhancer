# Hermes Enhancer v0.22.0 Beta

Beta release scoped to **process-crash/restart durability** of the
federated telemetry store. Install: `chmod +x setup.sh && ./setup.sh`.

## Highlights

- Crash-safe persistent event buffering (`event_buffer`, UNIQUE `event_id`)
- Durable buffer-before-final-persistence ordering with post-commit finalization
- Automatic startup recovery, bounded to 100 rows per invocation
- Idempotent event persistence (retried pushes return the existing row id)
- Retry/recovery handling (transient backoff, permanent/unknown surfaced, buffer failures fail-loud)
- SQLite health validation (`verify_database`, never deletes data)
- Malformed-buffer handling (FAILED + diagnosis, rows preserved)
- Multi-process writer validation
- Automatic installer (`setup.sh`) and safe uninstall (`uninstall.sh`)

## Validation (tmp_path-isolated automated tests)

- 10K sequential push: 10000/10000 unique, 0 loss, 0 duplicates
- 10K concurrent (8 threads): 10000/10000 unique, 0 loss, 0 duplicates
- 6000 multi-process (4 x 1500): 6000/6000 unique, integrity PASS
- Crash recovery (os._exit subprocesses): buffer-crash, post-commit crash, 120-event, repeated restart — 0 loss, 0 duplicates
- Failure injection: lock, tx failure, buffer-write failure, corrupt payload, duplicate, worker interruption, simulated ENOSPC
- Recovery backlog: exact [100 x 5] batches on 500 pending rows
- Installer: 8/8 (fresh, 3x repeat, upgrade, uninstall scope, double uninstall, missing-file failure, state.db sentinel)
- Combined focused suites: 49/49 PASS; SQLite quick_check + integrity_check PASS on all final states

## Compatibility

v0.21 public APIs unchanged and backward compatible: `push`,
`get_recent`, `count`, `async_push`, `flush`.

## Known Limitations (not beta blockers)

- Power-loss / OS-crash durability NOT validated (`synchronous=NORMAL`, no fsync)
- Physical disk-full NOT directly tested (deterministic simulation only)
- Telemetry counters are process-local and reset on restart; DB state is the durable source of truth
- No universal exactly-once claim. Tested guarantee: no duplicate persisted `event_id` and no loss of confirmed durable buffered events across tested normal process crash/restart scenarios.
